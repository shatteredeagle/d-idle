## Required edits

1. **HIGH (code, claim commit).** `Fight::player_fighter` (`components/game/fight/strike.cpp`, the new block): the held weapon must skip a broken item (flag 0x100) and one short of its requirements (0x4000). game.exe's `FUN_00623990` takes the weapon from `FUN_0063c9b0`, which returns slot 4 if it is of type `weap` (`FUN_00629bb0(item, 0x2d)`) **and** `FUN_0062a4e0(item)` is true, else slot 5 under the same test, else nothing (V read, `0x63c9fb..0x63ca2c`, `0x63ca5e..0x63ca8f`); `FUN_0062a4e0` is false for an item with flag 0x100 or 0x4000 (`0x62a4f8..0x62a516`). d2d already models that function: `rules::item_usable` ("Usable (FUN_0062a4e0): not broken (flag 0x100) nor flagged 0x4000", `rules.hpp:1320`), and `player_fighter`'s own `weapon` (the loop above, through `gear_active`) is exactly game.exe's choice: usable, kind 2, right arm first. The new block re-walks the items without that filter and its comment says the opposite ("worn or not ... U: that the game's held weapon ignores the requirements"). Measured (V run, probe below): an Amazon or Sorceress with a broken or requirement-short sword gets start 2 (game.exe: row 0, start 1), with a broken bow start 0 (game.exe: 1): 505 of the 540 such cells differ on the claim. Fix: replace the block with
   `fighter.attack_start = d2d::rules::attack_start_frame(actor->character.character_class, weapon && base_of(weapon) ? wclass : "")`, i.e. reuse `weapon` (look up its `item_base` for `wclass`; keep "no base record -> barehanded row" or skip as now), and drop the "worn or not" comment. Add one frozen cell to `test_swing_start` (a Sorceress with `ssd` flagged 0x100: start 1 on the SOA11HS record; take the ticks from the oracle with the weapon class forced to none) so the rule is pinned, and let `swing_start.py` say in its docstring that the held weapon's choice is hooked (it is: `FUN_00623990` returns the fake item).
2. **MEDIUM (doc, claim commit).** `docs/research/re/combat.md`, new section, third bullet: "its strike one tick late in 1,195 of 11,200 cells" matches no count. The oracle (V run, `swing_start.py compare` on the oracle commit's grid) gives **1,267 of 11,620** cells without a start frame (1,123 of 8,890 for the five other classes, 144 of 2,730 for Amazon / Sorceress bow, crossbow, claws and the non-A1 modes). Use those.
3. **MEDIUM (doc + draft).** Fend is not a sequence: its `anim` is A1 (skills.txt, V run: the probe lists `ama A1 Fend`; Jab and Impale are SQ). `skill_sequence()` needs `anim == "SQ"`, so in the claim Fend's swing takes the start frame (V run: Fend's `set_pmode` length 16 -> 14, 14 -> 12, ... with a 1hs). That matches game.exe (A1 takes the start frame for any skill; native `FUN_00623b10` sweep below), so the code is right and the text is wrong in three places: combat.md last bullet "a sequence (Jab, Fend: `start_sequence`)", the draft's "Jab and Fend (the `start_sequence` path ...) are unchanged" and "Fend's sequence keeps its length". Say: Jab and Impale (SQ) unchanged; Fend (A1) gets both rules.
4. **MEDIUM (draft collateral).** Throws are not unchanged. `missiles.cpp:278` sets `kModeA1` for a skill whose anim is TH, so a throw now strikes on `attack_action_tick` (start 0) instead of the old formula: 56 of 360 TH cells (Amazon javelin skills, Lightning Bolt) strike one tick earlier, the swing length unchanged (V run, `T` lines). game.exe plays the TH record there, which d2d does not, so this is neither closer nor further from game.exe in a way the oracle can show. Move "TH" from "Not changed" to the collateral list: "a throw (TH, which d2d plays on the A1 record) gets the strike rule only; its record is still d2d's A1 (not checked)".
5. **LOW (wording, code comment + combat.md + oracle docstring).** (a) `FUN_006235a0` is a class test, not "dual wield": true for a player of class 4 or 6 (Barbarian, Assassin) and for monster classes 0x1a1..0x1a2 (V read `0x6235a0..0x6235f8`). Say "S3 and S4 only for a Barbarian or Assassin (`FUN_006235a0`), whose entries are 0". (b) The `kAttackStart` comment says a class key the map lacks "starts on 0 here": game.exe's `FUN_00629fe0` returns row 0 for it (`0x62a040 xor ax, ax`), so an Amazon or Sorceress gets 1 (V run: key `zzz` -> 1 in the native sweep). No vanilla weapon has such a key (weapons.txt `wclass`: 1hs, stf, 1ht, bow, 2ht, ht1, xbw only), so either return `by_class` of row 0 for an unknown key or fix the comment. (c) The end's floor is 2, not 1: `FUN_005539b0` files the end at `frame + max(n, 1) + 1` (combat.md says so a few lines above the new section); `max(1, ceil(...))` only differs when one tick covers the whole remaining animation (rate >= 256 (frames - start)), which no player record reaches (attack rates stay under 450, frames - start >= 6). Write "max(2, ...) (never reached by a player swing; the closed form d2d uses is the same for every real record)" or keep `max(1, .)` and say why it does not matter.

Optional (S, not blocking): split the claim commit into the strike-tick rule (all classes, start 0) and the start frame (Amazon, Sorceress); upstream's AGENTS.md asks for "one claim or one code change per commit" so a reviewer can drop one, and these are two functions' claims (FUN_005539b0's rounding, FUN_00623b10's table).
