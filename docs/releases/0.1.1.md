## What changed for the friends (plain words)

- The hero no longer gets stuck bouncing between a warp and the area next to it: after arriving, the bot walks away from the warp before it does anything else, and if it still loops it avoids the deeper area for a while.
- It picks up gold first and remembers where loot lay; potions are drunk and refilled more sensibly (belt layout, refill, a fallback that drinks from the pack), and it keeps a buffer of 4.
- It remembers which Den of Evil it already cleared; the level plan data knows Blood Raven (level 8) and the level exits.
- Paladin: a new fighting profile with Sacrifice and an aura choice. Sacrifice is ON by default, guarded (only at 70 percent life or more, and only with a potion in the belt). It has not run live yet (U), see the known limits.
- The watch page: map fog of war, a Skills page (read-only class skill trees), Gear Sets with drag and drop (unlocks at level 15), a tidy button, and dropping items works on the click path.
- Safer updates: the bot only applies an update when the hero is in a safe spot (otherwise it says "try again"), runs a self-test, and checks free disk first.

Item verbs stay off; the friends image plays through the normal clicks. The d2d engine is unchanged: the same fork commit `acadbe47f989553bb7ee53299c18695c9226e8fa` (branch `fork-only/art-clean`) and a byte-identical d2d binary (sha256 `1a642471cdcd5539ef01a7c9518e4a0e9f734561570012d5d6fa4e2bd960f99e`), so the feed's d2d source tarball is the same file as in 0.1.0. The bounce fix is bot-side (V: root cause found in the bot), so the d2d arrival-spot fix (`fork-only/sandbox-warp`) is not included.

## Known limits

- Paladin Sacrifice shipping ON is a judgement, not a live result: it is covered by tests only (the live-check list in docs/palprofile.md has not run). Its cost is capped by the life guard, so it cannot kill the hero by itself; if a friend's Paladin burns potions, set the knob `combat.sacrifice` to 0.
- A new release counts as healthy only after 10 minutes of stable play; an update applied during that time rolls back to the previous release, not to the one before.
- The 0.1.0 client has no safe-spot check: it applies an update at once, even in a fight (the hero is saved first and kept, V). Friends who update from 0.1.0 should press update while in town.
- Linux x86-64 with Docker only. No Windows or macOS bot. Windows/macOS d2d is parked.
- Hero state is per container volume; no backup or sync.
- Art on the overlay stays off. The window icon was not seen on a real display (U).
- 20 other merged items since 0.1.0 are docs or research and change nothing for a friend. One research branch (decomp13) did not merge and is not shipped.

## Update and install

- A friend on 0.1.0: the watch page shows the update banner (Update button), or run `./didle update` and answer y while the hero is in town. The pack and image are not needed (abi unchanged).
- A new friend: `sha256sum -c didle-friends-0.1.1.tar.gz.sha256`, `tar xzf`, `./install.sh --game-dir /path/to/Diablo-II`, open the printed address, pick a hero, start. Ports 8891 and 8892, 3 GB free, own Diablo II 1.14d files.

## What to tell the friends

Same as 0.1.0 (docs/releases/0.1.0.md): private test, offline, bring your own files, the address with the token is your password, `./didle report` writes a scrubbed file to send back, stopping takes up to 45 s. Plus: if you are on 0.1.0, update from the banner while the hero stands in town.
