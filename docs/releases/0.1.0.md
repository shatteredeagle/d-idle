## What it is

The first private friends release: a tarball (`didle-friends-0.1.0.tar.gz`) that installs the d.idle bot on d2d (headless Diablo II 1.14d engine, offline, no Battle.net) in one Docker container on a Linux x86-64 machine with Docker and the compose plugin. The friend brings their own Diablo II 1.14d folder (mounted read-only, never copied). One command installs; a short browser setup picks the hero; the watch page shows the run; `./didle update` takes signed releases.

## Known limits

- Linux x86-64 with Docker only (user decision 2026-11-10). No Windows or macOS bot.
- `UPDATE_FEED` points at the public feed, which holds no release until you publish; `./didle update` finds nothing before that.
- The release assets' `SOURCE.txt` names the public fork URL with the private commit in words; before publishing the feed, check the wording against the GPL offer (the pack itself carries the exact source and the offer).
- Hero state is per container volume; there is no backup or sync. A fresh hero levels from scratch.
- Art on the overlay stays off (non-monetised stream allowance, art off by default). The Steam launcher art in the fork source tree still shows the Freepik skull (attributed, not in the image).
- Not seen: the window icon on a real display, the banner drawn in a browser, the non-DEV update path end to end.

## Install (Linux with Docker, for the friend)

```
sha256sum -c didle-friends-0.1.0.tar.gz.sha256
tar xzf didle-friends-0.1.0.tar.gz && cd didle-friends-0.1.0
./install.sh --game-dir /path/to/your/Diablo-II        # reads the licence note, asks y, loads the image, starts d.idle
# open the printed http://localhost:8891/setup.html?t=... address, pick a hero name and class, press Start
./didle status | stop | start | update | report
```

Needs ports 8891 and 8892 free (`--port N` changes them), 3 GB free disk, and your own Diablo II 1.14d folder (`d2data.mpq`, `d2exp.mpq`, `d2char.mpq`, `Patch_D2.mpq` at least).
