# Scenario corpus

Recorded real failure situations replayed offline as end-state regression tests (card gen-corpus; study: docs/research/bot-generality.md section 5 #2). They run in the normal `go test -short` set: fast, no game, no network, virtual clocks. Each is `TestScenario_<Name>` next to the code it drives, because the fakes (`rig`, `sim`, `harness`) are unexported in each package and a separate package would copy them. Each has a knob-off subtest that EXPECTS the old failure, so the corpus proves it can detect the bug. Evidence tags: V = VERIFIED in a log, I = INFERRED.

| scenario | evidence | invariant it pins | test | knob-off proof (old failure reproduces) |

Notes
- CampaignStall is driven step by step (planner verdict, then the stall hook, one virtual minute per step), not through `Runner.Run`: the real loop farms a banned area anyway after its idle cap (`areaskip.go`) and the failsafe ladder pauses the bot on a failed walk, so the live wall needs the nav wedge that WedgePocket pins. The corpus pins both halves.
- Run: `go test -short -count=1 ./internal/nav ./internal/bot ./internal/town ./internal/combat -run TestScenario` (the town test needs `D2_DATA_DIR` unset and the extracted tables, like `basicsaudit_test.go`: run it on the worker host).
