## 2. internal/d2dsoakstat (gatev2, minute, metrics, compare) and cmd/d2dsoak

The Poisson maths is right: `poissonSF` is the exact tail by summation, `poissonLower` the exact Garwood one-sided bound by bisection (run: lower(1)=0.0513, lower(3)=0.8177, lower(10)=5.4254, lower(100)=84.14 = chi2/2). Zero exposure gives INCONCLUSIVE (gatev2.go:86), the gap sign and tolerance in `Compare` are right, `Compare` treats NaN as INCONCLUSIVE, a 0-death baseline uses 0.5 (spec). The problems are around the maths, not in it:
- **H** `cmd/d2dsoak/main.go:178-187`: only FAIL exits 3; INCONCLUSIVE exits 0; with `-json` the function returns at :179 before the exit, so even FAIL exits 0 and `-save` is skipped. Scenario: `d2dsoak compare -json ... && echo PASS` prints PASS on a FAIL. Spec soak-gates "Verdict" wants exit 0 only for PASS. Fix: compute the exit code before the JSON/text branch; INCONCLUSIVE = 2, FAIL = 3.
- **H** `cmd/d2dsoak/run.go:229-231` with `internal/d2dsoakstat/metrics.go:53-55`: `Extract` returns an empty Run when fewer than 2 minute lines exist, then `finish` sets `res.Hours = hours` from the d2d clock. A seed whose bot crashed at start contributes its full virtual hours as 0-death, 0-kill exposure (run: three empty 2 h runs -> DeathsV2 PASS "0 deaths in 6.0 h"). Fix: leave `Hours` 0 (or mark the run `Short`) when `Minutes < 2`, and have `DeathsV2` skip such runs.
- **H** `cmd/d2dsoak/run.go:140-142,172-177` + `main.go:100-113`: a seed that ends "cmd exited" (non-zero, `CmdErr` set) or "wall limit" is kept as a normal run; a failed `runSeed` is skipped and the run continues with fewer seeds, exit 0. A 5-minute crash counts as a clean short seed. Fix: `End != "hours reached"` -> flag the run, warn in the verdict, exit non-zero when `len(runs) < len(seeds)`.
- **M** `cmd/d2dsoak/run.go:244` (`splitInts`): duplicate seeds are not rejected; `-seeds 1,1,1,1,1` runs one deterministic seed five times into the same `seed-1` dir, SD 0, passes `MinSeeds` 5 (run). Fix: dedupe and reject.
- **M** `internal/d2dsoakstat/compare.go:239-247`: `MinHoursPerSeed` (2 h) and `MinTotalHours` (10 h) only warn, verdict can be PASS (run: 5 x 0.2 h -> v1 PASS); fidelity-gate "Minimum sample" says MUST. Fix: INCONCLUSIVE below the minimums.
- **M** `internal/d2dsoakstat/gatev2.go:84-102`: NaN/Inf pooled hours skip every case (NaN compares false) and land in `default` = PASS (run: `Hours: NaN`, 0 deaths -> PASS "0 deaths in NaN h"); reachable through `extract -hours Inf` (metrics.go:59 accepts it). - **M** `internal/d2dsoakstat/minute.go:51` + `metrics.go:66-68`: a timestamp that fails to parse is left as the zero time; a bad first line makes Hours = 2.56e6 and xp/h ~ 0 (run). `minute.go:73`/`metrics.go:85`: a garbage `xp` reads as 0 and biases XP by a whole run (run: last line `"xp":"x"` -> XP -5000). - **M** `internal/d2dsoakstat/gatev2.go:124-127` (`DeathsPerKillV2`): no minimum kills; 1 kill 0 deaths = PASS; baseline kills 0 or baseline hours 0 gives a null rate of 0 so any death is p=0 FAIL (run). Fix: INCONCLUSIVE when baseline exposure is 0 or kills < a floor.
- **M** `internal/d2dsoakstat/metrics.go:142-148` (`repeatSites`) with :83: a counter jump of N appends N death records then scans O(n^2); a jump of 1e5 took 6.9 s, 1e9 would exhaust the head box's memory (run). Fix: cap per-minute increments (e.g. 1000) and warn.

## 3. cmd/d2dview (tap, read-verb whitelist, SSE, /stream, /api/pub)

The viewer socket is read-only as far as this side can enforce it: `readOnly` (mux.go:58-84) whitelists exact first tokens and exact field counts, so any whitespace variant (tab, CR, NEL, U+2028 all split by `strings.Fields`) changes the count and is refused; case is exact; `screenshot` needs `shotDir/` prefix and no `..`. Token auth uses `subtle.ConstantTimeCompare`; Snap errors (socket paths) stay on the token-protected `/api/state`; `/api/pub` (pub.go:60-84) exposes only sanitized strings and numbers, `unsafeChars` strips `<>&"`. Frames go through the viewer socket under the same filter.
- **M** `mux.go:147-158` + `main.go:241-260`: `POST /api/mode?m=watch&speed=0.001` is accepted (`v >= 0 && v <= 1000`), and `afterStep` sleeps `n*40ms/speed` **holding `m.mu`**: a 25-tick step sleeps 1000 s and the bot is frozen for that long; switching back to fast does not cancel a sleep in progress. With `-open` or a loopback `-addr` without token, anyone on the LAN/box can stall the soak. Fix: floor speed at 1 (or 0.5), cap the sleep per step at a few seconds, sleep outside the lock, check the mode each 100 ms.
- L `mux.go:98` forwards the raw line, not `strings.Join(f, " ")`. The whitelist is exact on Go's notion of whitespace; if the fork's parser ever splits on another byte (`;`, `,`) a `state;click 1 2` line would pass the filter (the fork's parser is not in this repo: U). Fix: forward the normalized fields.
- L `mux.go:162` `os.Remove(path)` before Listen on any path: `-bot-sock` equal to `-upstream` deletes the live d2d socket, then the tap dials itself under `m.mu` and deadlocks the bot. Fix: refuse `botSock == upstream` and only remove an existing socket (Lstat mode).
- L `main.go:95,163-183,215-237`: no `WriteTimeout`, no write deadline and no viewer cap on `/events` (SSE) and `/stream.mjpg`; a stalled client pins a goroutine forever (d2watch fixed exactly this in 49c66c6, stream.go:17-33). `feed.Wait` polls every 20 ms per client. Fix: `http.NewResponseController(w).SetWriteDeadline` per frame and a small viewer cap, as d2watch does.
- L `feed.go:163-167`: on a transient `state` error `put(s, nil)` stores a Snap without `Dead += prev`, so the cumulative `deadSeen` resets to 0 (the stream page uses the bot's own kills via `max`, so it only shows when `-bot-api` is off). `feed.go:192-194` the `seen` reset at 5000 units re-counts old corpses. Fix: carry `prev` on the error path.
- L `pub.go:44` `secretWords` lacks the lab's machine, person and domain names (the full list is in `tools/publish/sanitize.py`) and the throwaway character names; the python sanitizer (section 5) is stronger; a goal title "go to the NAS" survives here but is dropped on the page only if the python scan runs on this feed (stream-grid 2.1 is not built). Fix: one shared deny list, generated from `tools/publish/sanitize.py`.
- L `main.go:141-143`: `?t=` sets the cookie before the token is checked (harmless) and the token travels in the URL (referer/log exposure on the LAN).

## 7. Pacer/LateClock (D2DLOOP, ECONOMY on master) and the DETLOOP guard (agent/detloop 62ce4b3, unmerged)

Master Pacer: `Sleep` holds `mu` for the whole step loop, failed steps charge the remaining ticks and wait the same wall time (the D2DPACE fix), `follow` carries virtual time across a d2d restart, `LateClock.Poll` steps 2 ticks + 10 ms wall (economy). Clean; one note: `sync()` sets `synced` even when the first `Clock` call fails (pacer.go:49-56), so the first successful `follow` jumps virtual time by the game's current ms (once, only after a failed start).
DETLOOP: `Watch` runs the runner's guard on the stepping goroutine after the chunk that crosses `WatchMs` (pacer.go:126-172 on the branch); `busy` prevents re-entry when the guard itself sleeps (the retreat sleep at loop.go:901); `fired` stops repeated cancels; the mutex is released around `fn()` and on the error path (read). `ex.Now = r.e.Clock.Now` is right. Two things to know before merging:
- **M** `pacer.go:Sleep` (branch): the guard now runs at most once per chunk, i.e. once per `Sleep` call when `d <= 2 s` (chunk 50 ticks). A single `Sleep(2s)` gives one look at the end instead of 40 looks at WatchMs=50 ms; death/safety/stuck reactions under lockstep can come up to 2 s of virtual time later than on Game.exe. Under lockstep nothing happens between steps, so this is a precision change, not a hole, but the soak numbers (deaths/h) should be re-baselined after the merge, and `Chunk` could be lowered to `WatchMs/40ms` while a watcher is registered. Fix: step in chunks of at most `every` while `watch != nil`.
- L `loop.go:guard` (branch): an action that blocks on wall time without calling `Clock.Sleep` (a `Do` timeout, `time.Sleep` in d2dctl reconnect) gets no guard look at all, and `gameEvent()` (socket gone) is seen only at the next Sleep. Same precision caveat; document in docs/d2d-determinism.md.
- L `pacer.go:Watch` keeps one watcher: a second `Watch` silently replaces the first. Today `guard` is the only caller (loop.go:341); add a panic or a counter so a future nested guard is noticed.
