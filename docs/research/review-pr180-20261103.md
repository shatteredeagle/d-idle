## 3. Tooling (axis 2)

- **Network, downloads, shell-out:** none added. `decompile.sh` runs a locally installed `analyzeHeadless`, `gaps.py`, `tee`; `presubmit.py` shells out to the local `g++`, `clang-tidy` and `tools/tidy-pr-select.py` with flags read from the contributor's own `compile_commands.json`; `.githooks/pre-push` runs `python3 tools/pr_guard.py --sorted` (V read). No secrets in the diff (V read: grep of the diff for token/key patterns found none; U for a scanner run).
- **Pre-push hook:** opt-in (`git config core.hooksPath .githooks`), `--no-verify` skips. It takes `upstream/main` else `origin/main` as base, skips branch deletions. It runs the checked-out working copy's `pr_guard.py`, not the pushed commit's (I), so pushing a branch you are not on checks the wrong tree's script, not the wrong files (the files are read with `git show`). Fine for normal use.
- **Maintenance cost of the sorted check (Medium):** ASCII sort of `#include` lines, so quoted includes sort before angle ones in one contiguous block and a comment line splits a block. Only `win(sock|dows)|shlobj|objbase` blocks are exempt, so any other order-sensitive include (a config header that must come first, a macro before an include) needs a blank line to split the block (I). Address tables are exempt only when the heading or two lines above contains order/route/chain/sequence/in turn; an unrelated "Order" heading silently disables the check for that table (I, from `IN_ORDER`). Whole-file semantics mean touching one line in a file with an old unsorted block fails the PR; main is clean today for C++ (section 1) so the cost is zero until someone adds a stray include.
- **Local requirements and run time:** GCC and tidy run only when a `compile_commands.json` exists in the build dir or `tree/build`; otherwise one WARN ("one full presubmit run makes it"). Needs a real GCC (Homebrew `g++-NN`), llvm's `clang-tidy` (keg-only on macOS: the new `find_tool` looks in the Homebrew llvm dirs). TUs run on a thread pool sized by `build_jobs()`. The PR gives no timing for `--quick`; the PR body's "about a minute" for `decompile.sh` conflicts with the script header ("About 10 minutes") (V read: both strings). Low: doc inconsistency.
- **False-positive handling for tidy:** findings count only on lines the branch added, plus any `misc-include-cleaner` hit in a changed file (V read, `check_tidy`). So an include a branch drops fails even if the dropping line is not "added". The message says CI's older tidy may not flag others.

It splits rows without checking the column count (a malformed `symbols.tsv` throws; the shell wrapper then fails on "SCRIPT ERROR") (V read). `DecompileAll.java` now uses `grabFromProgram` options. `fn.py` reads `tools/ghidra/project/game_all.c` into memory (large file, local only).
