## 1. What is public, what is private
- PUBLIC: code (`cmd/ internal/ web/ deploy/ packaging/`), `openspec/` specs and cards, research and design docs, `README.md`, `LICENSE`,
  `THIRD_PARTY.md`, public rules (`AGENTS.md`, `GLOSSARY.md`, `docs/adr/`), generic CI.
- PRIVATE (d2lod-ops): lab layout (boardhost, soak hosts, runner and capacity docs, the third-party worker docs), scripts that drive the
  lab and its game instances (`tools/live.sh game.sh jobs.sh ...`), the status board and publisher (`tools/agentstatus`, `tools/publish`),
  stream and kick tooling, `.claude/agents/` (carry lab detail), `AGENTS.private.md`, `local.env`, go-live material (audit, this doc).
- Anything with a hostname, private IP, home path, person's name or machine name is never committed to the public repo.
- Manifest: `docs/process/public-manifest.json` (V: see `grep -c glob`; regenerated by package A). Classes `public | private | scrub-needed`; first match wins, `**` = public.
  `private` and `scrub-needed` carry a note; `scrub-needed` also a `replace` class (section 2). Hand-kept rules come first; the
  per-file scrub-needed entries are generated: `go run ./cmd/leakcheck -gen-manifest > docs/process/public-manifest.json` (keeps
  hand-kept rules, refreshes the generated ones from current hits; V stable on re-run). After the mass scrub there are no generated
  entries left and the private rules become the `git mv` list for d2lod-ops.
- Summary: after package A only the three go-live docs are private-listed; the rest of the tree is scrub-needed or public (V, section 8).

## 2. Host config and placeholder convention
- Public code and scripts never contain a lab value. They read env vars, with generic defaults, from the process environment or a
  gitignored `local.env` at the repo root (sourced by `tools/env.sh`, which also sets the defaults; Go: `internal/env`-style helper).
- Names are role-based, NOT machine-based (the machine names are themselves private): `D2_WORKER_HOST` (default `worker.example`),
  `D2_WORKER_USER`, `D2_NAS_HOST` (`nas.example`), `D2_BOARD_URL` (`http://board.example:8897`), `D2_FORGE_URL`, `D2_COLD_DIR`
  (`/mnt/cold`), `D2_GAME_DIR`. Defaults use the reserved `.example` TLD (RFC 2606); never a real or `.lan` name.
- Prose: say the role, never the machine: "the worker host", "the NAS", "the status board", "the forge", "the maintainer". NOT allowed:
  "the worker host (Orion in our lab)", "Tower", or a first name. Paths: `$HOME`, `~`, `/mnt/cold`. Game words stay (Forgotten Tower).
- Replace classes in the manifest: `env-var` (code/scripts: read the value from env), `placeholder` (prose: role word or example name),
  `redact` (a person's name or schedule: delete; the owner's own name becomes "the maintainer"), `split` (AGENTS.md), `manual`
  (secret or email shape: a human decides; most are code that handles tokens by reference and get an allow-list entry).
- Real values live in `d2lod-ops/local.env` (private, committed there); `tools/ops.sh env` prints it, `tools/ops.sh link` symlinks it to
  `local.env` in a worktree.

## 5. One-time cut procedure (go-live day; checklist, nothing run yet)
1. Quiet master: no active agent branches; every branch merged or abandoned (record the list in `docs/needs-you.md`).
2. Mass scrub merged (section 6); `go run ./cmd/leakcheck -mode fail` exits 0; `sh tools/ci/check.sh --hygiene-only`, `go build ./...` ok.
3. Flip the gate: pre-push hook `-mode warn` -> `-mode fail`, CI step "leakcheck (warn)" -> "leakcheck" without `|| true`.
4. Create `jesse/d2lod-ops` on Forgejo (private); `git mv` the private-class files there, keeping their history (`git filter-repo --paths-from-file`
   on a clone); push. Check out at `~/code/d2lod-ops`; run `tools/ops.sh link` in every long-lived worktree.
5. Fresh history: from the scrubbed master tip, `git checkout --orphan public-main`, one commit "Initial public snapshot" (maintainer
   identity or the agents' noreply identity; no stash refs, no branches), tag `v0-public`. Rewritten history is cut here: the old
   history stays only in the Forgejo archive repo (step 7).
6. Remotes: rename the old Forgejo repo to `jesse/d2lod-bot-history` (private, read-only archive); create `jesse/d2lod-bot` anew and push
   `public-main` as `master`; the user creates the GitHub repo `shatteredeagle/d2lod-bot` (empty, GPL-3.0-or-later shown, no Actions
   secrets, Wiki off) and pushes the same ref as `main`. Agents re-clone or `git worktree` from the new remote; old worktrees are discarded.
7. Branch protection (user, in the web UI): `main`/`master` protected, PR required for non-maintainers, status check `checks` required.
8. Verify: fresh clone on another machine, `go build ./...`, `go test -short ./...`, `go run ./cmd/leakcheck -mode fail` on it.
9. Docs: update `docs/publish.md`, ADR 0010 addendum with the public URL (coordinator), delete `docs/process/public-split.md` here
   (it lives in d2lod-ops).
