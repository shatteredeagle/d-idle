# Autoflip

User policy 2026-11-27: a finished feature goes to the sandbox and is monitored. `tools/flip/autoflip.py` plans and runs the flips so the coordinator does not flip row by row; `flip.py` stays the only thing that touches a sandbox.

- `autoflip.py plan [--json]`: reads the merged ledger view (`data/darklaunch/<knob>.json` plus the flip tool's runtime state file, docs/process/dark-launch.md); takes rows with status dark and owner coordinator (never `by_design`, never owner rows). Instance, bundle group, window and value come from the row's optional `flip_plan` {instance, bundle, window, value}, else from `tools/flip/autoflip.json` by knob prefix (`quests.`/`items.`/`loot.` to questy, `combat.`/`town.`/`bot.`/`nav.`/`invdesk.`/`ui.`/`input.` to doofer; names in `log_only_rows` go to both). A knob that the deployed build of the instance does not list in `ops status --why` knobs is skipped with the reason. Bundle = same instance and group, at most 6 knobs (more split into further bundles). Only one bundle per instance is ready; the rest are QUEUED (one window per instance). Prints the exact `flip.py ... --window 2h` line per bundle.
- `autoflip.py run [--dry-run]`: per instance, the first bundle only; refuses when a window is open or a hard counter is nonzero; runs the flip.py dry-run first, then the real flip, and ends with a one-line summary. The watcher (`flip.py watch`) must be alive.
- `autoflip.py graduate-list` (card flipfix2): every row the runtime state or the merged view calls enabled, checked against the per-knob files `data/darklaunch/<knob>.json` and `docs/knobs.md`. READY (clean close, the state note `graduation_note: graduation-ready` the watcher writes at CLOSE is shown in the heading with `enabled_at` in EST): prints the file of the default (`Key: "<knob>"` in `internal/env/tuning*.go`), the grep of the knob name in non-test Go (old-path sites), the ledger edit and `- check:` notes (criteria_met not yes, git still says dark with the one-line commit, no note, no `[dark-launch]` tag). HOLD (one line): `criteria_met` no, an owner row, a window with the knob open, enabled by hand without criteria. PROBLEM (one line, exit code 1): a state row without a knob file, a revert after the close, `enabled_at` before the end of the window, a knob that is not in `docs/knobs.md`, a code default that already is the trial value. Rows git calls default-on, retired or by_design are history and not listed. A revert before a later clean close does not block. It edits nothing: hand the text to a worker as the brief of a graduation card.
- Instances are sandbox aliases from `tools/flip/sandboxes.json` (alias -> container name and role: doofer is the canary, questy the quest sandbox) or container names; `"both"` in a `flip_plan` means every sandbox of the default plans. State files and `trial_instance` keep the container name.

Tests: `python3 -I tools/flip/test_autoflip.py` (fake sandbox of test_flip.py; `GraduateCheckTest` builds a per-knob directory and a state file).
