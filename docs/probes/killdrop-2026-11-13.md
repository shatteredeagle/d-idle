# Kill drop on the rebased fork: `debug players` gained a column (TASK-396, 2026-11-13)

> status: result record. Tags: V = run and seen on the worker host; S = read in source. Follows docs/fork-rebase-2026-11-13.md section 5.

## Cause (V)

Upstream d2d commit `4307d9c8` (2026-11-11, "LAN: players on their own levels") appends the player's level id to every `debug players` line: `id name x y seat pmode ghost level` (S: `apps/d2d/devctl/debug_net.cpp`; V: the reply on `dd70428d` is `1 Rebasv 28.00 48.00 -1 -1 0 2`, on the iv1 d2d the same line without the `2`). `d2dctl.ParsePlayer` counted the fixed fields from the end, so on the new d2d it read the name as `Rebasv 28.00`, x as the real y, y as -1 and the level id as the ghost flag. `d2dinput.Controller.Pos` (the hero's position for the navigator) was therefore wrong, `nav PathTo` found no path, and combat's `assess` dropped targets as `unreachable` ("no path and no firing position with a clear line of sight").

Class (a): an upstream format change the bot must follow; not a fidelity regression and not an artefact of the rebase (the suspects were checked first: the merged `click` verb is used 12 times a run and the bot attacks through `cmd skill`; lockstep is off in realtime runs; the read-only `debug` verbs the bot calls all answer without `--lab-verbs`).

How it was found (V): hero speed per leg equal (7.8 to 8.2 subtiles/s new, 8.0 to 8.7 old); kill time split walk/cast/wait showed the loss in `wait` (9.6 s against 3.9 s per kill); `debug grid 5`, `grid`, `blocked`, `layout`, `level`, `presets`, `portals`, `npcs`, `ground`, `states` answer byte-identically on both builds (seed 7, Blood Moor); for all 38 `unreachable` targets of a 5-minute sampled run a BFS on d2d's own `debug grid 5` found a path from the hero to the monster; `debug players` was the one bot-read verb whose shape differed. No bisect was needed: `git log -S` on the verb names the commit.

## Fix

`internal/d2dctl/parse.go`: a tab-separated `debug players` line is read from the front (`id name x y seat pmode ghost [level [quest bits]]`, new `Player.Level`, -1 when absent); a space-separated fixture line keeps the old end-anchored rule. `TestParsePlayerColumns` covers the 7, 8 and 9-column replies and a spaced name. Not build-specific.
