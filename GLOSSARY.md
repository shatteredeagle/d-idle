# D.idle (d2lod-bot)

A native Go bot that plays classic Diablo II Lord of Destruction 1.14d offline (softcore) as an idle game, plus the tooling, soaks and specs that judge it. Vocabulary below is written from the repo (2026-10-30); `UNSURE` marks entries I could not confirm from the docs. Agents do not edit this file (AGENTS.md, "Agent skills").

## Language

### Product and backends

**D.idle**:
The product name: the idle-game layer on top of the bot (upgrades and prestige are parked until the bot plays well). Lives in `PLAN.md`, `docs/INDEX.md`.
_Avoid_: using it for the repo name; the module is `d2lod-bot`.

**Game.exe backend**:
The original game under Wine on the worker host, read through `/proc/pid/mem` and driven by input injection (the `d2input` helper). It is the acceptance target. Lives in `internal/mem`, `internal/input`, `docs/d2-1.14d-memory.md`.
_Not to be confused with_: the d2d backend.

**d2d backend**:
A native reimplementation of D2 (psi29a/d2decomped, GPL) driven over its control socket by `internal/d2dsrc` and `internal/d2dinput`. ADR 0002: likely primary, gated on proof. Results from it are tagged V-d2d and are not acceptance results. See `docs/d2d-backend.md`, `docs/adr/0002-d2d-primary-backend-gated.md`.
_Not to be confused with_: Game.exe backend.

**d2d**:
The upstream program and its private fork on the worker host (`~/d2d-lab/fork`, never in this repo). Also loosely "the d2d backend". See `docs/d2d-spike.md`, `docs/d2d-fork.md`.

**fork**:
Our private, GPL-bound copy of d2d on the forge `<owner>/d2d-fork`; patches never enter this repo and every patch is pushed the same day. `docs/d2d-fork.md`, spec `openspec/specs/lab-rules`.

**lab binary (d2d.lab)**:
The fork build with every verb our tooling needs (`dump`, `step`, `clock`, `debug layout`); read-only and never overwritten. `docs/d2d-lab.md`.
_Not to be confused with_: lab2.

**lab2 (d2d.lab2)**:
The current default lab binary: lab rebased plus the vendor-price and cast-timing fixes (Akara tome 450, cast period about 13 ticks). `start.sh` uses it. `docs/d2d-lab.md` section "lab2".
_Not to be confused with_: lab (older base, kept for restore via `D2D_BIN`).

**lockstep**:
The fork's mode where the game advances only when told (`step <n>`), headless, about 100 to 380 times real time and deterministic for equal seed and inputs. `docs/d2d-fork.md`, spec `fidelity-gate`.

**devctl**:
d2d's control-socket protocol (`--devctl PATH`), single client, no auth; our client is `internal/d2dctl`. `docs/d2dctl.md`.
_Not to be confused with_: the `d2input` helper (Game.exe input port).

**control socket**:
The Unix socket of one d2d (`<run dir>/d2d-<instance>.sock`); a bot never attaches to one it did not start unless `--d2d-attach`. Spec `backend-contract`, exclusive resource `d2d-control-socket`.

**Pacer**:
The fork clock adapter whose `Sleep` steps the game in lockstep (virtual time); wrapped by `LateClock` in the bot. `docs/d2d-bot.md`, `docs/d2d-exit.md`.
_Not to be confused with_: the wall clock used on Game.exe.

**StateReader**:
The `d2.StateReader` interface (Snapshot, Player, UI, Units, UnitStats, ReadStatList, ReadBaseStatList, RawStatList) that both `*d2.Reader` and the d2d snapshot source satisfy. `internal/d2`, spec `backend-contract`.

**env.Env**:
The struct decision code uses to reach the game (`Read`, `In`, `Mem`, `World`, `Clock`, `Emit`); new code must not import a backend directly. `internal/env/env.go`, spec `backend-contract`.

**seam**:
A package boundary where a backend can be swapped (StateReader, input.Controller, Clock, env.Env). `docs/d2d-backend.md` section on seams, spec `backend-contract`.

**Worker host**:
The 16-core EndeavourOS box that runs every live game, d2d and soak; reached by ssh, shared and loaded. `AGENTS.md`.

**Head box**:
The 4 GB headless box agents work on; whole-repo tests go to the worker host. `AGENTS.md` "Memory limits".

### Gates, soaks and health

**soak**:
A long unattended bot run judged by numbers, driven by `tools/soak/soak24.sh` and `cmd/d2soak`. `docs/soak24.md`, spec `soak-gates`.

**G1**:
The 2 h original-game soak gate (stability, progression, belt, kill recovery). Passed on the harness at attempt 18 except kill injection. `docs/review-strategy.md`, `docs/g1-log.md`, spec `soak-gates`.
_Not to be confused with_: G2, the 24 h soak, or the d2d fidelity gate.

**G2**:
The 8 h original-game run (profile m24), a stability and economy soak, not a progression soak, until Andariel and Act 2 work. `docs/plan/plan-v2.md` s5, spec `soak-gates`.
_Not to be confused with_: G1.

**24 h soak**:
The 24 h runbook (`soak24.sh start iN`, profile m24 default). Merged, never run to the end. `docs/soak24.md`.

**profile m1 / m24**:
Soak judging profiles: m1 for the 2 h gate (XP floor off), m24 for long runs. `cmd/d2soak`, `docs/soak24.md`.

**soak attempt**:
One numbered G1 or G2 run in `docs/g1-log.md` (append-only); numbers there are the history.

**d2d fidelity gate**:
The replicated soak on lockstep d2d versus the original-game baseline, pass when each gated metric is within 20 percent. `docs/d2d-soak.md`, `docs/d2d-fidelity.md`, spec `fidelity-gate`.
_Not to be confused with_: G1 and G2 (those run on the original game).

**fidelity**:
How closely d2d's statistics (XP/h, kills/h, deaths/h) match the original game. `docs/d2d-fidelity.md`.

**health guard**:
The rule deciding when live work or a soak may start: tick age and frame times healthy, memory and disk fine, at most 2 Game.exe; load is only a backstop. Planned in `docs/review-strategy.md` section on health guard, dispatcher use in `docs/process/dispatcher-brief.md`. UNSURE: how much is implemented versus planned (soak start guard in spec `soak-gates` is load plus disk only).

**start guard**:
The implemented refusal to start a soak at load above 12 or disk under 10 GB. Spec `soak-gates`.

**recycle**:
Between-goal restart of Game.exe to reset its heap (the Recycler); a pid change starts a new soak segment. `internal/launch/recycle.go`, `docs/soak.md`. d2d has no recycle (`docs/d2d-bot.md`).

**failsafe ladder**:
The bot's escalation when progress stalls, one rung per expired window. `internal/bot` (`escalate`), `docs/bot.md`.

**rung**:
One step of the failsafe ladder (1 close panels, 2 reset to town, 3 leave and re-enter, up to 5; rung 4 restart per `docs/soak24.md`). Soaks cap rungs at 2 per hour. UNSURE: exact rung 4 and 5 meaning, read `docs/bot.md`.

**sentinel**:
The watcher that handles a frozen or hung game; its actions are counted per hour. `internal/sentinel`, `docs/sentinel.md`.

**heap guard**:
Bounds on nav search memory and a soak alert at 8 GB RSS or +1 GB in 5 min, added after attempt 16 hit 48.8 GB. Spec `soak-gates`, `docs/soak24.md`.

**kill injection**:
Deliberately killing Game.exe to test recovery (G1 criteria 6 and 7); needs the user's permission rule. ADR 0008, `docs/adr/0008-no-kill-injection-without-permission.md`.

**early baseline / late baseline**:
The reference XP/h and kills/h rates from the original game that the fidelity gate compares d2d against: the early one from fresh characters (clvl 1 to 7, `tools/d2dsoak/baselines-early.json`, `docs/d2d-baselines-early.md`), the late one from a cheat-levelled clvl 12 throwaway with the kit (card m2-latebase, `docs/d2d-baselines-late.md`). Spec `fidelity-gate`.

**paired seed**:
The same seed run under both arms of an A/B, so the analysis unit is the per-seed difference and seed noise cancels. Floor of 8 seeds. See **paired A/B**; `docs/ab-design.md`, `tools/ab/paired.py`.

**wedge**:
A permanent nav failure: a failed walk marked a route edge bad for good, so every route from that level read "no route" and the bot sat in town (navsoak runs lost 60 to 167 wall min). Fixed by expiring bad edges (`nav.badEdgeTTLSec`). `docs/townwedge.md`, `docs/probes/navsoak-compare.md`, spec `bot-loop`.

**pocket**:
A cell cut off from the gate on the known map grid; the usual cause of a **wedge**. The bot steps to the nearest connected cell and returns ErrNoPath, not ErrNoExit, so nothing is marked. `docs/townwedge.md`.

**stall ladder**:
Escalation when the campaign makes no progress on the virtual clock: WARN and a **fresh game** at `bot.stallWarnMin` (30 min), exit status 5 after `bot.stallExitMin` (30 more) so the supervisor restarts. Spec `bot-loop`, `docs/nowall.md`.

### Generality and evidence

**coverage**:
The axes a claim was proven on: seeds (count, holdout or not), class or build, act, difficulty, engine, start state, horizon. Outside them the claim is UNPROVEN, not PASS. `docs/research/bot-generality.md` section 3.

**transfer / transfer gap**:
How far a result survives a change of axis (a new seed, class or start state) with no policy code change, and how much each metric drops against the trained case (the gap). See **coverage**, **holdout seed**, **fidelity**.

**knowledge vs behaviour**:
Facts about the game (areas, monsters, builds, floors) belong in data tables loaded from game data; code only combines them. Raw area ids and class if-chains in policy code are the debt. `docs/research/bot-generality.md`.

**constant provenance**:
The tag on each number saying where it came from: measured (our logs), derived (formula from game data), judged (SME rule of thumb), fitted or arbitrary. See **knob**, **fitted constant**.

**fitted constant**:
A number picked so that one observed run passes. It widens the overfit surface; re-check it on holdout seeds or replace it with a measured one. One of the **constant provenance** tags.

**invariant**:
A property that must hold on every run whatever the axes: no hang past the stall ladder, no unrecoverable state, deaths bounded per 1000 kills, the character ends in town. Reported apart from **competence**.

**competence**:
How well a sound run plays: XP/h, kills/h, time to a boss. Judged only on runs that kept the **invariants**. Not the same as **power / danger / readiness** (the in-game risk model).

**holdout seed**:
A seed never used for tuning, fitting or diagnosis (seeds 16 to 23), reported as its own group. See **paired A/B** for how tuning runs are compared.

**differential proof**:
The primary proof of an upstream claim: the same inputs run through game.exe's own code under the emulator and through d2d's code, outputs diffed. Mismatches are counted before the patch (more than 0) and must be zero after. `docs/process/upstream-pr-standard.md` section 1.

**oracle**:
The emulator-driven harness that runs game.exe's real instructions on generated inputs and prints the lines d2d's test binary must match (hooks only on what is not the claim). Scripts in `tools/emu/*.py`. See **differential proof**.

**evidence pack**:
The one-page record of an upstream PR for the user's go: claim, proof summary, case counts and mismatches before and after, commands, residual risks, verifier verdict, `PROOF: complete|incomplete`, recommendation. `docs/research/pr-<topic>-evidence-pack.md`, standard section 7.

**bundle PR**:
One upstream PR carrying several proven claims, one claim and one commit each, each with its own differential proof, verifier verdict and ponytails; allowed at the maintainer's request (2026-10-31). Spec `upstream-pr`, standard section 4.

**ponytail**:
Upstream d2decomped's `// ponytail:` code note: a known gap or shortcut recorded where it lives. Every gap we know about in a patch gets one; a gap with no such note upstream is "silent" (`docs/d2d-gaps.md`). See **evidence pack**.

### Bot behaviour and guards

**NOIDLE**:
Rule that the bot never idles in town on an area ban: after `bot.areaIdleSec` (60 s) it farms the least-bad area. `docs/deathspiral.md`.

**ROUTEGUARD**:
Guard that enters the Monastery road and tower areas only with a living merc or clvl 20 and the supply kit. Agent name and rule; `docs/plan/plan-v2.md` s11.2, spec `merc-policy`.
_Related_: TOWERGUARD (the tower half, areas 20 to 25).

**TOWERGUARD**:
The tower-area half of ROUTEGUARD (skip the Countess quest without a merc). `docs/plan/STATUS.md`.

**BRKILL**:
Blood Raven kit gate and attempt logic that leads to the free Rogue. `docs/bossgate.md` section "Blood Raven gate (BRKILL)".

**free Rogue**:
The Act 1 mercenary reward from Kashya after killing Blood Raven; hiring any merc first forfeits it. ADR 0006, spec `merc-policy`.

**death rule**:
How deaths are judged: streak, recovery share and rate, not a fixed count. ADR 0005, spec `death-rule`, `internal/bot/deathrule.go`.

**recovery**:
The post-death phase (restock, corpse retrieval, broke-phase) and its states counted by FAIL-2. `docs/recovery.md`, spec `death-rule`.

**repeat-site ban**:
Area ban after repeated deaths in one area (30 min, escalating x4 and x12). Spec `death-rule`.

**kit**:
The supply set required before a field trip or boss (healing potions, mana for casters, town portal tome). See **kit gate**. Specs `early-game-policy`, `merc-policy`.

**Den first**:
Policy that a fresh character does the Den of Evil before anything else and takes the skill point. ADR 0004, spec `early-game-policy`.

**honest play**:
Running a character without cheats and with only earned gear; the baselines are an honest-play Sorceress clvl 11 to 14. `docs/d2d-soak.md`.

**knob**:
A tunable bot parameter with a dotted key and range (`group.name`). Defaults live in `docs/knobs.md` (generated from `internal/env/tuning_*.go`).

**campaign**:
The quest-driven goal sequence through the acts (templates `normal_act2`, `nightmare_all`, ...). `docs/actbot.md`, `docs/task.md`.

**goal**:
A unit of bot work held by the goal manager (level to N, quest, runs). `internal/goals`. UNSURE: exact term boundaries with "task".

**kit gate**:
`resource.recoveryKitGate`: while recovery runs with no healing potion or no town portal scroll, recovery farms only the near-town fields (Blood Moor, Cold Plains) and the navigator prices dungeon mouths. See **kit**. `docs/kitgate.md`.

**chicken exit**:
Leaving the game when life falls to `combat.chickenPct` (25 percent, Normal and Nightmare). Not the same as the flee of `resource.fleeLifePct`, which only breaks away from hostiles when there is no potion and no portal. `docs/knobs.md`.

**fresh game**:
A game the bot starts itself (`newGameRun`, e.g. `freshGameToLevel`, the **stall ladder**); per-game memory (cleared areas, sweep kills, buff need, step area) is dropped through `forgetGame`, as for any new game. Spec `bot-loop`, `docs/bot-small.md`.

**poverty loop**:
Recovery farming gold for a kit it cannot afford: poverty sell trips and portal scrolls bought, burned on the next emergency and bought again (62 percent of spending in the measured run). `docs/d2d-xp-gap.md`, `docs/recovery.md`, `docs/basics-audit.md`.

**champion / elite / boss**:
Kind classification: a champion (flag bit 2, no minions) is Elite plus a Champion label, never a Boss; Boss is a named unique or monstats boss. Boss alone gets pack danger 2. `docs/champions.md`, `docs/bot-small.md`.

**buy order**:
The shop's purchase sequence when poor: healing potions to the kit target (up to 3) first, then a Town Portal scroll only when the gold left covers it plus `town.tpScrollPotions` (2) potions. Specs `town-basics`, `early-game-policy`; `docs/basics-audit.md`.

### Milestones and decisions

**M0 to M11**:
The ranked work items of plan-v2 (M0 measurement, M1 fresh-character path, M2 Andariel gate, M3 to M4 merc reader and probe, M5 free Rogue, M6 to M8 merc revive/gear, M9 first Andariel, M10 skills past clvl 30, M11 corpse quit-restart). Status in `docs/plan/STATUS.md`, definition `docs/plan/plan-v2.md` s4.
_Not to be confused with_: the older milestones scoreboard `docs/milestones/milestones.json` (stale, different numbering).

**plan-v2**:
The master plan after the 2026-10-30 planning session; wins over `PLAN.md`. `docs/plan/plan-v2.md`.

**PLAN.md**:
The founding Wine-era plan, historical. `PLAN.md`.

**ADR**:
A user decision record, MADR style, `docs/adr/NNNN-*.md`, indexed in `docs/decisions.md`. Only the user or the coordinator writes them.

**V / S / U**:
Evidence tags: verified (say how), secondary source, unverified. V-d2d means observed on d2d only. `AGENTS.md`.

**EXP / SRC**:
Tags in the SME knowledge base: veteran judgment versus a user or SME statement needing a live check. `docs/sme/README.md`.

**milestone exit criterion**:
The measurable condition that closes one of the milestones M1 to M6 of `docs/roadmap.md`; it is owned by a spec and by the milestone's closing card, and progress is counted in these exits, not in merges. ADR 0012.
_Not to be confused with_: the plan-v2 items M0 to M11 above.

**deferred card**:
A change card queued behind a named dependency or user decision: status `deferred`, `owns:` and `exclusive:` intended but not claimed, no `docs/OWNERS` line. The dispatcher sets it `proposed` and adds the lines when the dependency merges. `openspec/README.md`, `docs/roadmap.md` section 4.

**paired A/B**:
A same-seed comparison of two settings run on matched seeds (see **paired seed**), so the difference is not seed noise. Protocol and tool: card m2-abdesign (`docs/ab-design.md`, `tools/ab`).

**power / danger / readiness**:
The rule of ADR 0011. Power is a character's survival (life, resists, potions, portal, merc), offense (kill speed against the area's real monsters) and clvl as a minor input; danger is the zone's monster level, real HP and damage, crowd, build-specific threats and our own death record there; ready means power >= danger x a safety margin. Until the model exists (card m3-readiness-model) clvl floors in merc-policy are the rule.

**keeper merc / throwaway merc**:
ADR 0011: a keeper is a merc that is a build's target merc or wears its target gear (always revived, never replaced to save gold); any other merc is a throwaway (re-hired when the hire price is below the revive price).

### Agents and process

**SME**:
Subject-matter expert agent; here the D2 veteran (`d2-sme`) whose advice the user trusts at about 99 percent. `.claude/agents/d2-sme.md`, `docs/sme/`.

**d2-sme**:
The read-only agent type that answers "does this make sense to play". `.claude/agents/d2-sme.md`.
_Not to be confused with_: spec-sme (how to write specs and cards).

**spec-sme**:
Read-only advisor for specs and change cards. `.claude/agents/spec-sme.md`.

**change card**:
One job: `openspec/changes/<id>/` with proposal.md and tasks.md (header block). The unit of work and the issue-tracker equivalent. `openspec/README.md`, `docs/agents/issue-tracker.md`.

**spec**:
A stable contract in `openspec/specs/<capability>/spec.md` (requirement and scenario form). Numbers live here.

**delta spec**:
A spec change inside a card (`## ADDED|MODIFIED|REMOVED Requirements`), applied at archive. `openspec/README.md`.

**owns**:
The path globs only one active card may edit; mirrored in `docs/OWNERS`.

**exclusive**:
Shared resources only one active card may use (`instance:iN`, `d2d-control-socket`, `d2d-lab-binary`, ...). `openspec/README.md`.

**gates (card)**:
The acceptance lines of a card, each a number or a named test.
_Not to be confused with_: G1/G2 (soak gates) and the fidelity gate.

**changecheck**:
`go run ./cmd/changecheck [-cli]`, the card, spec, OWNERS and STATUS checker. `cmd/changecheck`.

**archive**:
Moving a finished card to `openspec/changes/archive/YYYY-MM-DD-<id>/` with `merge:` hash; done by the coordinator.

**coordinator / main agent**:
The session that merges, archives, restarts games and decides; workers do not. `AGENTS.md`.

**dispatcher / dispatch agent**:
A subagent launched per tick to merge finished branches, run tests, check cards and report soaks in 10 lines. `docs/process/dispatcher-brief.md`.

**worker agent**:
An agent with its own worktree `~/code/d2lod-wt/<name>` and branch `agent/<name>` (types d2-worker, d2-live, d2-researcher, d2-reviewer). `.claude/agents/`.

**status board**:
The live agent board at board.example:8897, updated with `tools/agentstatus/agentstatus.py`. `AGENTS.md`.

**grill agent**:
The preconfigured Opus main agent `.claude/agents/grill.md`, started by `tools/grill.sh <n> <slug>`; the user is its interviewee. Its guard hook limits writes to one ADR, one decisions.md line and `outcome.md`. `docs/process/grill-agent.md`.

**grill session**:
A dedicated user-run session of the grilling skills; the only place ADRs and the glossary are written. `docs/process/matt-pocock-skills-fit.md`.

**slot**:
One parallel hidden d2d instance from the pool of 4 (slot 0 is the legacy lock), taken with `tools/d2dslot.sh run`, each with its own socket and ports; a run holds exactly one, and a fifth waits or exits 75. Spec `lab-rules`.

### Instances and characters

**instance (i0 to i5)**:
One game: Wine prefix, Game.exe, `d2input` helper (port 47012+N) and character. Map in `tools/instances.conf`, `docs/multi.md`. i0 Testy (everyone else), i1 Navi (nav), i2 Combi (combat), i3 Towni (town), i4 Booti (bot, also the G1/G2 soak), i5 Multi.
_Not to be confused with_: a d2d instance (own socket per instance).

**throwaway characters**:
Testy, Botty, Navi, Combi, Towni, Booti, Multi, Palli, Palli2, Necki, Amazi, Druki, Assi, Barby: the only ones that may be cheated, offline, via the ledger. `AGENTS.md`.

**Soaky**:
The Sorceress used for most G1 attempts (clvl 11 to 14, not cheated, damaged history); the d2d baseline character. `docs/d2d-soak.md`, `docs/BACKLOG.md`.

**Fresha**:
A fresh clvl 1 softcore Sorceress created on i5 for clean fresh-start soaks. `docs/decisions.md`, `docs/soak24.md`.

**cheat ledger**:
The logged record of every test cheat; cheats go only through `internal/cheat` and `cmd/d2cheat`, each with a reason. `docs/cheats.md`.

**OOG**:
Out-of-game menus, start, leave and crash restart (`internal/launch/oog*.go`, `cmd/oog`). `docs/oog.md`.

**d2input**:
The helper process that injects input into one Game.exe instance. `docs/multi.md`.

**live.sh**:
`tools/live.sh <agent> <pkg>`: the only way agents run against a live game (build, ship, flock, ptrace setcap). `AGENTS.md`.

**d2fleet / container**:
The supported product path: a container where the bot owns the game per slot, set up by a wizard. ADR 0001; native worker host stays the dev path. `docs/container.md`, `docs/fleet.md`.
